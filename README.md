# Fishermen Pants — Hugo clone

Static Hugo clone of https://www.fishermenpants.com, hosted on GitHub Pages.
No backend: cart and search are client-side, payment via PayPal JS buttons,
newsletter via Formspree. No customer accounts/authentication.

## Layout

- `content/` — products, collections, static pages (generated by the tools, then hand-editable)
- `data/home.json` — homepage section data (banners, featured products, tiles, testimonials)
- `layouts/` — site theme (baseof + section templates)
- `static/` — CSS, JS, and all product/banner images (`static/img/`)
- `tools/` — migration tooling:
  - `crawl2.py` — paced crawler of the live site (respects `Retry-After`)
  - `build_content.py` — turns `_crawl/parsed.json` into Hugo content
  - `mksearchindex.py` — regenerates `static/js/search-index.json` from content files

## Build

```bash
./build.sh            # -> public/  (add HUGO_BASEURL=https://<user>.github.io/fishermenpants-com/ for Pages)
```

## Deploy (GitHub Actions)

Pushing to `master` runs `.github/workflows/pages.yml`: installs Hugo,
rebuilds `public/` (with the Pages baseURL) and deploys via
`actions/deploy-pages`. The repo's Pages source is set to **GitHub Actions**
(build type `workflow`). Site: https://alx.github.io/fishermenpants-com/

## Re-crawling the source site

Shopify's edge rejects plain HTTP clients (403/429), so pages are fetched
with a real browser (Playwright Firefox) in `tools/crawl_browser.mjs`:

```bash
python3 tools/crawl2.py jobs        # write _crawl/jobs.json
node tools/crawl_browser.mjs        # phase A: browser crawl (paced, retry-on-429)
python3 tools/crawl2.py bc          # phase B: CDN images -> static/img, phase C: legacy parse
python3 tools/parse_products.py     # parse product/collection pages -> parsed.json
python3 tools/build_content.py      # content/ + data/home.json
./build.sh && python3 tools/verify.py
```

## Configuration (hugo.toml → params)

- `params.paypal.clientId` — PayPal REST client id. Set to a live/sandbox id
  with "Pay with PayPal" enabled; buttons render on product pages (selected
  variant) and the cart page (order total).
- `params.formspree.endpoint` — Formspree form endpoint, e.g.
  `https://formspree.io/f/abcdwxyz`. Used by the "Get 10% off your first
  order" form at the bottom of the landing page.

## Features

- Client-side cart in `localStorage` (`static/js/cart.js`), cart page with
  quantities, line items and subtotal
- Client-side search (`static/js/search.js`) over `static/js/search-index.json`
- PayPal Pay buttons (PayPal JS SDK) on product and cart pages
- Country/region selector on cart page and footer (persisted, no backend)
- Formspree email capture on the landing page
- No customer authentication anywhere
